# i3system MES (프론트엔드)

적외선 영상센서(IR Image Sensor) 조립/검사 라인용 MES 화면입니다.
관리자용 생산 대시보드와 작업자용 생산실적관리 두 화면으로 구성했고,
React 19 + Vite + Chart.js 기반입니다.

## 실행

```bash
npm install
npm run dev       # 개발 서버
npm run build     # 프로덕션 빌드 (dist/)
npm run preview   # 빌드 결과 미리보기
npm run lint
```

## 화면 구성

메인(`#/`)에서 관리자 화면과 작업자 화면을 고른다. 라우팅은 별도 라이브러리 없이
`App.jsx`에서 해시(`#/admin`, `#/worker`)로 처리하며, 상단바의 로고를 누르면 메인으로 돌아간다.

### 관리자 화면 — 생산 대시보드 (`#/admin`)

| 영역 | 컴포넌트 | 설명 |
| --- | --- | --- |
| 상단 바 | `TopBar` | 로고(메인 이동) · 타이틀 · 실시간 시계 |
| 요약 지표 | `SummaryBar` | 금일 총 생산 / 목표 달성률 / 양품률 / 가동 라인 / 금일 불량 |
| 라인 현황 | `LineCard` ×3 | 생산완료율 링 게이지, 생산·불량·잔여·시간경과 미터, 로트 메타 |
| 로트 관리 | `LotTable` | 상태 필터 · 검색 · 열 정렬 · 완료율 막대 · 상태 칩 |
| 설비 상태 | `EquipmentPanel` | 설비(행) × 라인(열) 매트릭스, 상태별 집계 |
| 불량 유형 | `DefectPanel` | 금일 불량 파레토 |
| 생산 추이 | `TrendCard` ×3 | 전체 물량 일간(7일) · 주간(8주) · 월간(12개월) |

### 작업자 화면 — 생산실적관리 (`#/worker`)

| 영역 | 컴포넌트 | 설명 |
| --- | --- | --- |
| 생산정보 | `ProductionInfo` | 작업일자·공정·로트·제품·시작/종료시간, 전체·생산·불량 수량 |
| 작업지시 | `WorkOrderCard` | 지시번호·품번·품명·작업자·바코드 생산량, 진행률/불량률 미터 |
| 검사치수 | `MeasurePanel` | 수집된 측정값, 규격 이탈 값 강조 |
| 작업 이력 | `WorkLog` | 조작 결과 로그 |
| 조작 패널 | `ActionPanel` ×3 | 작업 시작/종료, 양품/불량 등록, 보조 기능 |

작업 시작·종료가 시각을 기록하고, 양품/불량 등록이 수량과 잔여수량에 반영된다.
공정 마감은 작업 종료 이후에만 동작한다.

## 차트

Chart.js 4 + react-chartjs-2를 쓰고, 등록과 공통 기본값은 `src/charts/chartSetup.js`에 모았다.
색은 `index.css`의 CSS 변수를 `palette`로 읽어 쓰기 때문에 토큰만 바꾸면 전 차트에 반영된다.

| 차트 | 타입 | 비고 |
| --- | --- | --- |
| 생산 추이 | bar + line 혼합 | 구간별 목표는 계단형 점선, 막대는 달성(초록)/미달(주황) |
| 불량 유형 | 가로 bar | 막대 끝 건수·비중은 로컬 플러그인(`defectValueLabels`)으로 표시 |
| 생산완료율 | doughnut | `cutout`으로 링 두께를 맞추고 가운데 수치는 HTML 오버레이 |
| 요약 스파크라인 | line | 축·툴팁 없이 추세만 |

진행률 미터(`Meter`)와 로트 표의 완료율 막대는 차트가 아닌 진행 표시라 CSS로 유지했다.

## 디자인 규칙

- **토큰 기반**: 색·반경·그림자·타이포는 모두 `src/index.css`의 CSS 변수. 브랜드 컬러는
  i3system 로고 기준 `#006cb8`이며, 테마는 라이트 단일이다.
- **상태 색은 단독으로 쓰지 않는다**: 정상/점검요/정지 등은 항상 아이콘 + 라벨과 함께
  표시해 색각 이상·흑백 출력에서도 구분된다 (`StatusChip`).
- **미터의 색 위계**: 생산개수만 브랜드 컬러, 불량개수는 관리한계(3%/5%)에 따른 상태 색,
  잔여수량·시간경과는 중립색이라 카드에서 한 지표만 주목된다.
- **반응형**: 1440px 미만에서 로트 관리 표가 한 줄을 통째로 쓰고, 1280px 미만에서
  라인/추이 카드가 2열 → 1열로 접힌다. 작업자 화면은 1180px 미만에서 조작 패널이
  본문 아래로 내려간다.

## 라인 구성

| 라인 | 제품군 | 대표 품목 | 공정 |
| --- | --- | --- | --- |
| Line 1 | 냉각형 MWIR | Super MARKOS SL (T2SL 1280×1024 / 10㎛) | In 범프 플립칩 본딩 · 디워 진공 실링 |
| Line 2 | 비냉각형 LWIR | TE-EQ2 코어 (µ-Bolometer 640×480 / 12㎛) | 웨이퍼 레벨 진공 패키징 · 코어 조립 |
| Line 3 | InGaAs SWIR | InGaAs 1280 (1280×1024 / 10㎛) | 블랙바디 NUC 캘리브레이션 · 결함화소 검사 |

설비는 인듐 범프 플립칩 본더(FCB) · 웨이퍼 레벨 진공 패키징(WLP) · 헬륨 리크 테스터(HLD) ·
스털링 쿨러 조립기(SCL) · 블랙바디 캘리브레이터(NUC) · 결함화소/NETD 검사기(AOI) 6종이며,
불량 유형도 결함화소 초과 · 진공도 저하 · 범프 접합 불량 · NETD 규격 미달 등 검출기 공정
기준으로 구성했다.

## 데이터 연동

관리자 화면은 `src/data/mockData.js`, 작업자 화면은 `src/data/productionData.js`를 쓴다.
`Dashboard.jsx`의 `useLiveLines`가 4초마다 가동 라인 실적을 올려 실시간 갱신을 흉내낸다.
실제 연동 시에는

1. `lines` / `lots` / `totalTrend` / `equipment` / `defectTypes` / `workOrder` 형태를 그대로
   반환하는 API를 붙이고,
2. `useLiveLines`를 폴링 또는 WebSocket 구독으로 교체하면 된다.

컴포넌트는 모두 props만 받는 표시 전용이라 데이터 소스 교체에 영향을 받지 않는다.
